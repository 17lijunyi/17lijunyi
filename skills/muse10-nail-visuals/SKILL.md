# Muse10款式生成

将参考照片转换为同一套穿戴甲的商品视觉：**款式与指位清单 → 固定模板中的十片母版 → 同款双手佩戴 → 局部特写 → 商品图库**。三张图表现同一套作品的不同视角。已有作品的尺寸或背景被指出不对时，进入模板校准，保留已确定的款式。

## 已记住的默认偏好

- 一套准确十片，对应左右手十指；每排是一只手，从左到右为拇指、食指、中指、无名指、小指。两排第一片分别是左右手的拇指甲，因此甲片本体更宽。其余指位也各有尺寸，不能画成十片等大的甲片。
- Muse10 当前陈列模板固定为 4:5。不同款式共用[固定背景](assets/catalog/background.png)及[十指定位基准](assets/catalog/template.json)：只更换美甲款式，甲片本体的宽高、位置、间距、留白与背景保持一致。不是每款重新画一张近似的蓝色背景。
- 默认交付三张素材与独立可交互预览。若用户本次只要某张图片、只讨论或只要规则，按实际范围交付。
- 默认只做预览，不修改、部署或接入现有网站。用户已明确授权网站修改时，可以继续对应工作，不要求重复授权。
- 使用新上传照片的颜色和款式。示例中的花束、城堡、粉宝石、丝带只是案例，不能自动加进别人的作品。
- 用户本次明确要求的数量、背景、版式和范围优先于这些默认偏好。
- 用户说“先不要生成”“只讨论”时暂停生成和网站改动；先准确复述其要求，收到继续实施的指令后再执行。

## 1. 从原图建立十片设计清单

实际查看用户照片，区分手机界面、底盘、桌面和甲片；识别甲型、底色、材质、浮雕、装饰及每片的差异。

为左手和右手各五片指定稳定编号 L1–L5、R1–R5 与真实指位，记录每片主要设计和本体尺寸，后续图像保持对应。数量多于十片且用户要求十片时，优先精简重复度高、装饰较简单的款式，简短说明取舍；不要把十一片作为十片交付，也不要悄悄融合两种重点款式。用户同时要求“全部保留”和“准确十片”且无法兼容时，才需要澄清。少于十片时，只有在任务允许设计延伸时才补齐，不把补全内容说成原图已有。

十片不等于十种不同款。原图已有的对称或重复设计应保留；防止的是生成过程意外重复、漏款或为了凑数复制。

区分图像角色：**用户照片决定款式；陈列参考决定背景和排版；手模参考只决定姿态、镜头与光影。** 不把原站或示例款式混入用户作品。

## 2. 固定模板，再生成或校准款式

先读取[陈列标准与问题修正](references/catalog-standard.md)。用户指定另一张陈列图时，以该图重新建立模板；不要把 Muse10 当前像素坐标强加给其他模板。

区分三个尺度：商品卡外框、每片甲片本体、伸出甲片的立体饰品。外框同为 4:5 不代表甲片尺寸正确；整体缩放不能修正十指比例；花束、丝带或宝石的外接框不能代替甲片本体宽度。按十个指位分别校准，重点比较两片拇指甲与其余四指。

固定背景包含色调、亮度、渐变位置与细颗粒纹理。复用同一背景素材，避免偏亮蓝、云雾状明暗、额外投影或每款独立调色。生成和图像编辑遵循当前 `imagegen` 技能及工具规则；已获准采用原图抠图与合成时，将背景和甲片分层处理。不能用反复整图重生成代替尺寸与背景校准。

按[图像提示词](references/prompts.md)制作或修正甲片，保留原作核心装饰、颜色和手工质感。需要透明素材时检查真实 alpha；RGB 棋盘格不等于透明底。不得为了塞进陈列位而硬裁饰品、拉扁宝石或补出明显假边。

实际数清十片，按指位清单检查本体尺寸，再与参考等比例并排核对背景、位置和留白。必要时使用 `scripts/check_catalog_background.py` 核对高清母版的画布与共享背景像素；它不能代替指位和外形检查。未通过的结果不能称为“一比一”。母版的确认默认是完成这轮检查；只有用户明确要求先确认时才等待回复。

## 3. 以母版生成佩戴图和特写

母版确定后才能开始衍生图。可并行生成佩戴图与特写，但两者必须使用同一最终母版；若特写依赖佩戴姿势或精确指位，则顺序生成。

- **双手佩戴图**：两只真实自然的手，每手五指，十片甲片对应十个真实指甲。两片较宽的拇指甲必须戴在实际拇指上，食指至小指也按清单对应；不要按“图片左边”判定解剖左右手。让十片尽量完整可见，检查多指、缺指、非原作的重复或缺失、漂浮饰品、不自然贴合及遮挡。
- **局部特写**：选一至三片重点设计，拍摄真实手指上的近景。继续核对同套颜色、装饰和比例；若是佩戴图的特写，保留对应指位，不任意换指。

每张都实际看图检查，发现问题做针对性修正。核心数量或解剖问题未解决时，不把图片称为合格成品。不要承诺 AI 重绘是像素级一比一，必要时简短指出细节差异。

## 4. 制作独立作品预览

需要在对话中看效果时，使用当前 `visualize` 技能。读取[图库交互与打包](references/gallery.md)，可复用 `assets/gallery-template.html` 和 `scripts/build_preview.py`。

保留的交互规则：

1. 默认显示十片陈列图；鼠标进入图片时临时切到佩戴图。
2. 仅悬停后移出，恢复陈列图；手动翻页后移出，保留当前图片。
3. 图片左右侧、垂直居中的细箭头用于翻页，画面水平滑动，不做实时“把甲片贴到手上”的动画。
4. 手机支持横向滑动，纵向滚动保持正常；无悬停设备也能使用箭头。
5. 点击图片或作品名称可看大图，能返回图库；键盘可以操作。
6. 多件作品使用三列陈列。只有一套作品时展示一个可切换卡片，不把三种视角伪装成三套作品，不为填列复制同一套作品。加入原站作品作参照时明确标注。

若用户要求重看某网站或视频，实际查看后再适配交互；只保存本方法，不能把旧观察当作网站永远不变的事实。历史参考为 https://aniccanails.com/collections/all 。

## 交付与复用

- 预览文件使用任务自己的持久输出位置。复制进网站、上线和分享链接属于另一项明确的实施动作；本技能本身不表示已经接入网站 AI 服务。
- 图片预览用绝对本地路径显示；交互预览按当前 `visualize` 技能的输出格式显示。避免未经提供就编价格、库存、购买入口。
- 接入已有商品区时复用相邻商品的图片外框、名称与价格排版，按用户指定位置加入同一网格。作品应有名称；售价未提供时明确待定，不能用“十片套组”冒充价格，也不要让缺少售价阻塞已授权的视觉修正。
- 简短告知如何切图；无需重复解释工具实现。需要说明时，将生成图称为效果预览。
- 本技能的花园款示例：[陈列预览](assets/examples/master.jpg)、[双手佩戴](assets/examples/wear.jpg)、[局部特写](assets/examples/detail.jpg)。它们用于说明视角与交互，不能替代本次用户款式；陈列预览是压缩副本，精确背景以 `assets/catalog/` 中的母版为准。
