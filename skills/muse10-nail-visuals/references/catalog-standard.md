# 固定陈列模板与问题修正

用于 Muse10 款式生成、用户指出“尺寸还是不对”“背景颜色不同”，或要求“左图为模板，只换款式”的情况。

## 这次反馈明确了什么

| 用户指出的问题 | 应采用的规则 | 检查依据 |
| --- | --- | --- |
| 数量应为十片，并有上手效果 | 一套对应左右手十指，三张图是同款的陈列、佩戴、特写 | L1–L5、R1–R5 指位清单 |
| 两排第一片应更大 | 第一片分别是左右手拇指甲，本体更宽；其他四指也各有比例 | 看甲片本体，不能以花束的宽度证明拇指够宽 |
| 图片外框一样大，里面甲片仍不对 | 对齐每片本体宽高、位置、排间距与留白，不能只整体缩放 | 等比例并排或叠加比较十个陈列位 |
| 背景颜色明显不同 | 共用同一底图，固定色调、亮度、渐变与颗粒纹理 | 核对共享背景像素及整体观感 |
| 要放在原商品区域，缺少名称与价格 | 同一网格、相邻卡片相同外框与文字排版；名称和价格各自明确 | 检查网页实际卡片，未知售价明确待定 |
| 先停下来理解，再实施 | 讨论阶段不继续生图；明确实施后执行已确认要求 | 当前用户指令与最近一次纠正 |

## 当前 Muse10 模板

- `../assets/catalog/background.png`：1200 × 1500 的无甲片背景，源自用户指定的左侧陈列参考。保留原有灰蓝到灰白渐变；原甲片遮挡区域以同一高度的干净背景补齐。它不是对被遮挡原始像素的恢复。
- `../assets/catalog/template.json`：对应两只手的十个陈列位、指位、参考宽高与位置。坐标是这张商品图的屏幕排版基准，不是可直接下单的毫米尺码。
- 第一排 L1–L5，第二排 R1–R5；每排均按拇指、食指、中指、无名指、小指陈列。拇指更宽，中指可以比食指更长，不能机械地让五片等大或逐片等比例递减。

用户另给模板时替换这两个基准，保留相同的检查方法。其他品牌不自动沿用 Muse10 底图。

## 校准方式

1. 先锁定背景及十指设计映射。确认每片甲的本体轮廓，单独标记伸出本体的花瓣、丝带、宝石等饰品。
2. 分别对齐十片本体的宽高和中心位置，再核对行距、列距与边缘留白。固定模板仍须保留甲型的自然轮廓，不以图片元素等宽证明尺寸正确。
3. 复用固定背景素材。在用户要求背景一致时，不让生成模型为各款另画背景，不用 CSS 蓝色遮罩、亮度滤镜或整体缩放来掩盖偏差。
4. 饰品与甲体分别检查。不要把整个花束外接框强缩到拇指宽度，导致拇指本体反而比食指窄；也不要拉扁宝石、截断丝带、制造收腰或假边。若原图无法同时保留这些约束，明确具体冲突，不交付明显变形的结果。
5. 需要透明素材时核对文件确有 alpha 与透明像素，不能只凭棋盘格外观判断。按当前工具规则选择已获准的生成、抠图或合成方式。
6. 图像通过后接入商品卡。网页外框默认 4:5，禁止额外缩放主图改变已经对齐的构图；图片格式转换与缩略图压缩另存副本。

## 验证与修正顺序

先检查：两手十指和款式映射 → 每片本体尺寸与甲型 → 固定背景 → 饰品完整性 → 网页卡片与交互。

背景检查脚本仅检查高清陈列图的画布和陈列位以外的共享背景，需要 Pillow：

```bash
python3 /absolute/skill/scripts/check_catalog_background.py \
  --image /absolute/work/master.png
```

默认使用包内模板并要求共享背景像素不变。若流程明确采用有损压缩，可显式传入 `--tolerance`，同时记录误差；不得把放宽阈值后的通过说成逐像素一致。不要将压缩预览当作高清母版送检。

脚本通过不能证明数量、指位、甲片大小或饰品没有变形，仍须实际看图。做网站构建、卡片外框相等或图片加载成功，也不能代替这轮视觉核对。

同一问题再次出现时，先定位是哪一层错了；不要继续用同一种整图缩放或模糊的“相似背景”提示词反复尝试。报告具体完成项和仍有的差异，不先宣称“一比一”。
