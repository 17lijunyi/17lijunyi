# AI 产品简历修改 Skill

**给已有简历的 AI 产品经理、FDE 和转型求职者使用：在真实经历的基础上，修改定位、项目表达、数据口径和排版，交付可直接使用的修改稿。**

它提炼了九份由提供者认定经过市场检验的简历中的可迁移优点，让 Agent 学会如何从原稿中识别优势、组织证据、突出关键判断。每个人保留自己的经历与风格，按目标岗位选择修改方法。

## 给什么人用

| 适用人群 | 能帮助修改的重点 |
| --- | --- |
| 在职或求职的 AI 产品经理 | 把用户问题、范围取舍、AI 方案、评测迭代与实际结果连起来，减少只有功能和术语的描述 |
| Forward Deployed Engineer（FDE）及相近交付岗位求职者 | 突出真实的客户需求、系统集成、部署、调试、验收与反馈，准确表达本人贡献 |
| 从设计、运营、保险、机械、土木等领域转向 AI 产品的人 | 展示领域判断、流程经验与质量标准如何进入已有 AI 实践，建立清楚的转型主线 |
| 投递上述岗位的应届生和早期求职者 | 整理教育、研究、实习和独立作品，区分工程测试、试点使用与真实用户结果 |

使用前需要一份已有简历。可以是正文、可读取的文件或完整页面图片；目标岗位和 JD 有则提供。没有 JD 也可以修改。只有缩略图时，Agent 应说明阅读范围，并请求可读正文。

## 会改什么

- **定位与顺序：** 找出原稿最强证据，调整优势、工作、项目和教育的权重，让职业主线容易理解。
- **经历与项目：** 清楚表达解决的问题、本人判断、贡献和结果；工作写范围，项目展开证据，减少重复。
- **AI 产品能力：** 从实际经历中突出模型与规则分工、人机协作、方案取舍和评测迭代。
- **数据：** 讲清前后值、单位、适用条件，区分百分点、相对增幅、耗时和产能，以及测试、预计与实际成果。
- **排版：** 调整信息层级、段落密度、对齐、重点和分页。依据资历与内容量选择篇幅，不规定所有人一页。

保留真实职位、日期、贡献层级和产品阶段。有数字就写清楚，没有数字就使用真实交付与验证证据。原稿已经有效的内容可以保留，不要求每段重写。

## 怎么用

将整个 `ai-product-resume-edit` 文件夹放入支持 Skill 的 Agent 环境，加载 [SKILL.md](./SKILL.md)。Codex 本地安装示例：

```bash
git clone https://github.com/17lijunyi/17lijunyi.git
mkdir -p ~/.codex/skills
cp -R 17lijunyi/skills/ai-product-resume-edit ~/.codex/skills/
```

然后附上已有简历并发出请求：

```text
请使用 $ai-product-resume-edit 修改我附上的简历。
目标是 AI 产品经理，保留真实经历和贡献边界。
重点优化项目表达、数据口径和排版，给我可直接使用的修改稿。
```

也可以只修改一个部分：

```text
请使用 $ai-product-resume-edit，只修改我原稿中的采购助手项目。
下面是原文和目标 JD，请保留其他经历。
```

```text
请使用 $ai-product-resume-edit，按这份 FDE JD 调整我的已有简历。
重点突出实际集成、部署、调试与验收经历，准确区分独立完成和协作贡献。
```

## 你会得到什么

1. 修改后的整份简历或指定部分；文件可编辑时，提供修改版并保留原稿。
2. 简短说明最关键的修改及保留的优势，必要时提供原文对照。
3. 少量影响可信度或岗位匹配的待确认问题，确认后回填对应内容。

能读取与编辑哪些格式，取决于使用它的 Agent 环境。只有文本时提供可复制稿；有文档编辑与渲染能力时，进一步修改文件并检查实际页面。它不会凭空声称已排好或检查过 PDF。
