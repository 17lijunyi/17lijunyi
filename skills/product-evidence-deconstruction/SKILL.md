# 产品证据拆解

把用户提供或授权查看的真实产品证据转成可审计的产品拆解报告。不要保存或套用某个具体产品的名称、角色数、工作流或结论。

## 不可跳过的原则

1. **证据先于分析。** 产品名称、宣传文案和常识不是产品行为证据。
2. **先识别产品类型。** 不同产品类型使用不同观察重点；不要套用同一套固定问题。
3. **四层顺序固定。** 先用户层，再技术层、模型层、数据层；后一层必须能追溯到前一层观察。
4. **事实与解释分离。** 所有重要结论标记为【页面/代码事实】【合理推断】【尚未确认】。
5. **输出统一为 HTML。** 最终交付可独立打开的 `.html` 文件，而不是只在聊天中给出长篇 Markdown。

## 第一步：确定拆解任务

在取证前确认：

- 产品或功能边界：整个产品、一个项目、一个工作流，还是一个具体任务。
- 用户要回答的问题：用户旅程、能力边界、Agent 契约、技术架构、模型策略、数据流、商业化或综合拆解。
- 操作权限：只读、可否登录、可否点击已有预览、可否创建测试数据；不得把“拆解”理解成允许写入或付费。
- 可用证据：截图、录屏、可访问网址、导出文件、源代码、运行日志或用户提供的原始输入。

若用户没有说清拆解范围，但现有证据足以限定范围，采用最窄合理范围并在报告中声明。只有会实质改变结果时才询问。

## 第二步：证据门控

读取 [证据标准](references/evidence-standard.md)，建立证据清单和编号。

至少需要一种一手证据才能继续：

- 能覆盖目标流程的完整截图或录屏；
- 可访问的真实产品网址及必要的用户接管；
- 可读的原始代码、配置、接口定义或运行产物。

若证据只能支持局部拆解，应缩小结论范围。若没有一手证据，停止分析并输出：

1. `证据状态：不足`
2. 已收到的材料
3. 缺失材料及优先级
4. 获取材料的安全方式
5. 收到材料后将检查的范围

不得在证据不足时用宣传页、行业惯例或记忆补出完整流程。

## 第三步：识别产品类型并调整重心

读取 [产品类型路由](references/product-types.md)。先给出一个主类型，可附次类型，并说明判断证据。

类型不确定时，先做最少量取证区分，例如观察主要输入、核心输出、任务是否异步、是否有长期记忆、是否依赖生成模型。不要因为页面出现聊天框就默认是 Agent 产品。

## 第四步：按四层逐层拆解

读取 [四层框架](references/four-layer-framework.md)，按以下顺序工作：

1. **用户层**：目标、输入、操作、反馈、选择、纠偏、失败、中断、情绪和价值兑现。
2. **技术层**：前后端边界、任务状态、异步执行、工具/服务、依赖、错误恢复和可观察系统行为。
3. **模型层**：模型职责、输入输出约束、路由、生成/检索/评估、质量验证、安全与成本；无法看到模型或提示词时保持未知。
4. **数据层**：项目对象、资产、版本、引用、状态字段、生产者—消费者、持久化、失效传播和一致性。

每层完成后记录它为下一层提供的约束。示例：用户层观察到“满意后继续”，技术层检查是否是阶段门控，模型层检查是否触发重新生成，数据层检查确认状态如何写入及是否造成下游版本变化。

## 多 Agent 产品

只有页面或代码存在多个具名角色、编排节点或独立职责时，读取 [Agent 契约方法](references/agent-contract.md)。不要预设 Agent 数量，也不要把会话入口、模型名称或普通服务强行算作 Agent。

公开的“思考完成”“规划完成”只能作为用户可见判断摘要；不得声称读到了隐藏思维链。口头计划不能证明工具已执行，必须用资产、状态、工具结果或代码路径验证。

## 操作与取证

- 截图：查看完整画面及必要的放大区域，同时读聊天、按钮、表单、资产卡、错误和状态。
- 网站：优先只读浏览；需要登录、验证码或用户控制时交给用户，等待明确确认后再继续。
- 代码：从入口、路由、状态管理、数据模型、任务队列、工具适配器和错误处理追踪真实路径；区分定义、调用和运行结果。
- 多源冲突：同时记录，不自行选择“更像真的”一方。Agent 声称完成不等于资产完成，UI 卡片出现也不等于结果质量已验证。
- 不读取或输出凭证、Cookie、Token、浏览器存储中的敏感内容。

## 最终 HTML

读取 [HTML 输出规范](references/html-output.md)。将报告写成当前任务目录中的独立 HTML 文件，并在回复中提供可点击的绝对路径。

报告至少包括：查看范围、证据缺口、产品类型与拆解重心、四层结论、跨层数据流、事实/推断/未知、状态冲突、产品机会点、最值得继续验证的问题。只输出证据支持的章节；多 Agent 产品再加入 Agent 清单与 I/O 契约。

交付前验证：

- HTML 可独立打开、标题正确、导航可用、窄屏不截断核心内容。
- 每项重要结论能回到截图编号、页面原文、代码路径或运行证据。
- 没有具体产品名称残留在 Skill 本身。
- 没有把推断写成事实，没有编造官方工具名、模型名、字段名或 System Prompt。
