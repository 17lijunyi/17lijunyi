# 四层拆解框架

四层是观察顺序，不是四份互不关联的清单。每层都要回答“上一层观察在这里如何实现，下一层需要验证什么”。

## 1. 用户层

还原用户真正经历的旅程和价值兑现：用户、情境、目标；原始/补充输入、上传素材、表单和默认值；第一次和阶段反馈；满意/修改、继续/中断、方案选择和权限确认；正常、纠偏、失败与恢复；返回、撤销、版本、历史；最终查看、编辑、导出、分享或复用。

情绪、想法和痛点默认标为【合理推断】，除非用户明确表达。

输出用户旅程证据表和三泳道流程图（用户、产品界面、系统结果），节点标证据编号。

## 2. 技术层

从可观察行为或代码解释系统如何把输入变成状态和结果：客户端/服务端/队列/外部服务/存储边界；同步异步状态；功能性工具；权限与副作用；错误、重试、幂等、检查点和回滚；页面、聊天、任务、资产库、日志的一致性；进度、耗时、成本和错误可观察性。

页面未显示官方工具名时，使用“功能性名称，并非官方工具名”。代码中也要确认调用点，而不只看函数定义。

输出系统组件图、任务状态机、工具表和异常矩阵。证据不足时只写可观察技术层，不臆测后端架构。

## 3. 模型层

识别模型真正承担的职责：理解、规划、检索、生成、评估或路由；模型输入和输出；单/多模型或 Agent 路由；用户可选模型参数；知识和模板是否实际调用；质量验证者；内容安全、版权和敏感信息；成本、上下文、延迟和失败退化。

不要还原隐藏思维链、System Prompt 或未暴露模型名。公开计划只能描述为用户可见判断摘要。

输出模型职责矩阵、输入—判断—输出契约和能力边界。

## 4. 数据层

识别对象、字段、版本和引用：用户、项目、任务、会话、消息、资产、版本和权限；原始输入、配置、参数、确认和失败；生产者、消费者和读写时机；名称/URL/位置/稳定 ID关联；历史、分支、回退、删除和保留；上游修改的失效传播；只写不读、只读不写、孤立资产和重复状态；真相源；长期信息和敏感数据生命周期。

只给代码或页面支持的字段命名。分析提出的字段标记“分析命名，并非产品真实 schema”。

输出全局字段表、生产者—消费者表、版本/失效图和一致性风险。

## 跨层闭环

逐条连接：`用户动作 → 页面反馈 → 技术状态 → 模型/工具任务 → 数据写入 → 下游消费 → 用户看到的结果`。

任何一段没有证据都保留缺口。产品机会点应针对这些断点，例如状态真相源、版本透明度、成本预估、失败恢复或稳定引用，而不是泛泛提出“优化体验”。
