# HTML 输出规范

最终交付是当前任务授权目录中的独立 HTML 文件。文件名使用用户可识别的产品或项目标题；Skill 本身不固化具体产品名。

## 默认章节

1. 查看范围与操作边界
2. 证据清单与缺口
3. 产品类型与拆解重心
4. 用户层
5. 技术层
6. 模型层
7. 数据层
8. 跨层输入—状态—结果流程图
9. 状态冲突与风险
10. 产品机会点
11. 事实、推断和未知清单
12. 最值得继续验证的问题

多 Agent 产品额外加入 Agent 清单、I/O 契约卡、工具总表、全局字段表和生产者—消费者表。

## 展示要求

- 顶部写清证据范围、日期、产品类型和结论边界。
- 固定图例区分事实、推断和未知。
- 关键结论包含证据编号；证据列写原文、按钮、资产、错误或代码路径，不只写编号。
- 长契约卡使用 `<details>`；重要结论默认可见。
- 流程图表达输入、判断、工具/系统、输出和交接；判断节点写分支条件。
- 状态冲突并列显示，不消解冲突。
- 情绪、想法和机会点与事实分开，默认标为合理推断。
- 可以加入目录、响应式表格和打印样式；不依赖网络资源才能阅读核心内容。

## 质量要求

- 使用 `<!doctype html>`、UTF-8、viewport、语义标题和表格。
- CSS 内嵌、对比充足、支持 320px；宽表格局部横向滚动。
- 不使用外部追踪、网络请求或隐藏数据。
- 不把截图、源码或敏感内容内嵌成不必要的大型 base64。
- 交付前解析 HTML、检查章节和关键文本，并进行一次视觉或语义加载验证。

## 最终回复

说明文件已生成，提供可点击绝对路径，一句话概括证据边界；证据不足时说明报告停在哪一层。不要在聊天中重复整份报告，也不要未经确认扩展到 System Prompt、内部工具函数或其他超出目标的内容。
