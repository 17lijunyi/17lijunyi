# 多 Agent 产品的契约方法

仅在证据支持多个 Agent、角色节点或职责单元时使用。

## Agent 识别

按时间和依赖顺序记录名称/身份、加入时机、触发者、接替对象、下游交接、是否再次调用，以及本场景没有出现的常见角色。

不要把会话入口、模型名、普通按钮、后台服务、工具适配器或没有独立职责证据的 UI 标签自动算作 Agent。

## 六类输入来源

1. **用户当前输入**：需求、补充、素材、表单、满意/修改、继续/中断。
2. **用户长期信息**：语言、套餐、余额、资产、历史角色、音色、偏好、权限；只有证据才能写事实。
3. **项目全局上下文**：需求、配置、风格、角色/场景/资产、任务、确认、失败和版本。
4. **上游 Agent 输出**：生产者、传递内容、使用方式、修改后的重跑要求。
5. **平台公共资产**：模型、风格库、知识库、模板、安全/版权/计费规则。
6. **工具或运行时结果**：媒体、错误、中断、重试、地址、引用和写入失败。

## 可观察判断

只总结能观察到的功能判断：解决问题、必需信息、下一步、确认/自动继续/停止条件、修改和失败处理、完成标准、质量验证。每条标记事实、推断或未知。

## 工具调用

记录官方名称或“功能性名称，并非官方工具名”、输入、用户可见计划、实际调用证据、运行结果和失败/重试。资产出现可证明结果产生，但未必证明由哪个函数产生；代码定义也不能证明运行时调用。

## 五类输出

1. 用户回复：计划、说明、结果、错误、建议。
2. 页面组件：按钮、表单、选择、确认、错误和预览入口。
3. 资产：文本、图片、音视频、版本和引用。
4. 全局上下文写入：字段、状态、地址、确认、成功/失败。
5. 下游任务：目标 Agent、字段/资产、开始条件和确认门。

## I/O 契约卡

每个 Agent 使用固定结构：核心目标；触发条件；输入信息；可观察判断；调用工具；输出信息；全局上下文读写表（字段/对象、读/写、生产者、消费者、更新时机、证据等级、证据）；完成条件；异常与重试；尚未确认的问题。

## 全局检查

检查同一数据的多个版本；聊天、画布、任务、资产库是否一致；稳定引用；上游修改后的下游失效；只写不读/只读不写/无人生产的数据；口头完成但全局未更新；编排入口与专业 Agent 是否混淆。
